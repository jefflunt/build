# Decompose the bidirectional Node-RED workflow synchronization design into modular, actionable, implementation-focused units of work. Specifically, define tasks to update config resolution for standard flow file paths, build a semantic JSON normalization and SHA256 hashing package, and construct the `sync-flows` subcommand routing and bidirectional synchronization engine in Go.

Developers working with Node-RED frequently face a dilemma between modifying workflow files directly within an IDE or visually via the Node-RED UI. This project introduces a bidirectional sync mechanism, invoked via 'build sync-flows', to seamlessly reconcile changes across both environments. To solve the problem of infinite-loop triggering (where saving files updates modification times and triggers reverse syncs) and key-order/formatting differences in JSON responses, a semantic synchronization logic is used.

The synchronization process parses local and remote flows, normalizes them using Go's standard JSON library (which alphabetically sorts keys during map serialization and formats with 4-space indentation), and computes SHA256 checksums of the normalized outputs. If the checksums match, the flows are semantically identical, and the process exits immediately. If they differ, the sync engine checks the modification time of 'workflows/sdlc-orchestrator.json' against the active Node-RED flow file. The newer file determines the sync direction: either deploying the local JSON to Node-RED, or fetching and serializing the active Node-RED flow back to the local file system.
