# Develop the complete 'node-red-flow.json' definition file that implements the visual Dev -> Tester -> Test Suite -> Boss workflow, incorporating task serialization and locking to prevent concurrent or duplicate task processing. The flow must interface with the SQLite database to poll, route, execute agent CLI sessions, manage git sweep commits, and handle review or test result branches in accordance with the specified architecture design.

This task involves implementing the complete Node-RED workflow definition JSON file (node-red-flow.json) that replaces the hardcoded Go-based router execution loop. The workflow is triggered by a polling injector (e.g., every 5 seconds) and utilizes a stateful lock (task serialization) mechanism to guarantee that no concurrent or duplicate task processing occurs.

The flow will connect to the SQLite database (".build/build.db") to poll for active, stalled, or blocked tasks. For active tasks, it parses the assignee ID and routes execution to the appropriate agent sub-flow (Dev, Tester, or Boss). In each lane, the flow launches the agent CLI with contextual instructions and templates, executes a post-session sweep and git commit, and performs transition logic. For the Tester, it executes the workspace test suite ("./.build/test") and handles pass/fail escalations. For the Boss, it parses the JSON review output from comments and handles approval/rejection branches, resetting task attempts or escalating to the Lead engineer (Assignee 5) as appropriate.
