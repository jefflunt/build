# Refactor the main canvas orchestrator workflow in 'flows/sdlc-orchestrator-v1.json' to implement a Hub-and-Spoke layout containing a '/trigger-build' HTTP listener, global concurrency locks, and an iterative loop fetching tasks via 'build task next'.

This task entails refactoring the primary Node-RED orchestrator flow located in 'flows/sdlc-orchestrator-v1.json' to transition from a resource-intensive 5-second polling loop to an on-demand, event-driven Hub-and-Spoke architecture.

First, an HTTP POST listener endpoint '/trigger-build' will be implemented on the canvas to receive instant push triggers from the 'build' Go CLI. The listener must immediately return a HTTP 200 OK status to the caller to unblock execution, proceeding with the workflow asynchronously. Next, a global flow-level concurrency lock ('is_processing') will check and guarantee that only one orchestrator instance executes at any time. If locked, the execution safely aborts; if free, it sets the lock.

With the lock active, the orchestrator enters an iterative polling loop that runs the CLI command 'build task next' to fetch the next pending task. If a task is returned, the JSON is parsed to determine the appropriate assignee ('agent_id'), routing execution to the corresponding modular subflow (e.g., dev, tester, boss, sweep). Once the subflow finishes its execution and updates the task status via 'build task update', it returns back to the main loop to fetch the next task. The loop repeats until 'build task next' returns an empty task, at which point the global concurrency lock is released and the flow terminates.
