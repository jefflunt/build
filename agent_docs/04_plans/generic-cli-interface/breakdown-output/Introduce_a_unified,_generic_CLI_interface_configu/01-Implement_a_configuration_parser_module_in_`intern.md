# Implement a configuration parser module in `internal/config` to read `~/.build/config.yml` and parse the `agent_adapter` string into distinct CLI name, provider, and model components for use by the application.

Create a new module (likely in `internal/config`) responsible for locating, loading, and parsing the user's configuration file at `~/.build/config.yml`. The module must define a Go struct to represent the configuration properties. Specifically, it needs to handle the `agent_adapter` field by taking its raw string value (for example, `opencode:anthropic/claude-3.5-sonnet`) and splitting it into its underlying components: the CLI name (`opencode`), the provider (`anthropic`), and the model (`claude-3.5-sonnet`). This module will act as the source of truth for configuration data, exposing a clean API so the orchestrator and router can determine which LLM executable to drive.
