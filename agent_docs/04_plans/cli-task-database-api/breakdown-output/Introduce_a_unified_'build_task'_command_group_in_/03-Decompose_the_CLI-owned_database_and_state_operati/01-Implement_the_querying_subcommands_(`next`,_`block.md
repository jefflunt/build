# Implement the querying subcommands (`next`, `blocked`, and `stuck`) under the `build task` command group, including CLI routing in `cmd/build/main.go`, database access methods in Go, and structured JSON output formatting.

This task requires implementing the query subcommands `next`, `blocked`, and `stuck` under a unified `build task` CLI command group. The goal is to decouple Node-RED from direct SQLite queries, moving all database querying, business logic, and JSON output formatting into the Go-based `build` CLI. Each command must query the SQLite database (`.build/db.db`) and output clean, structured, and parseable JSON representing the matched task. If no task matches, it must print `{}` or `null` to ensure downstream systems process the empty response gracefully.

The CLI command routing will be integrated into the central Go CLI engine (specifically parsing subcommands under `build task` inside `cmd/build/main.go`). The `build task next` subcommand will retrieve the next actionable task that has status `todo` and whose children/dependencies are not also `todo` using the exact dependency logic defined in the workflows. The `build task blocked` subcommand checks if any task has the status `failed`, indicating a blocking issue that halts the workflow. The `build task stuck` subcommand checks if any task has the status `stuck`, meaning it requires Lead Engineer intervention.

Under the hood, database operations will use Go's SQL package to perform safe, read-only queries with appropriate connection safety, ensuring no database deadlocks occur when accessed concurrently. The JSON output format must be strictly compliant with the schema expected by the downstream Node-RED workflows, replacing the current direct shell executions of raw sqlite3 commands.
