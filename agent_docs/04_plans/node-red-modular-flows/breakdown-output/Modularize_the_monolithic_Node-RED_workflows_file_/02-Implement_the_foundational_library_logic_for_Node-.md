# Implement the foundational library logic for Node-RED flow modularization by defining the sync state tracking structures (storing metadata in `.build/sync_state.json`) and creating the partitioning engine inside `internal/syncflow/` to split a flat Node-RED JSON flow array into discrete tab, subflow, and global config partitions.

This task involves defining and implementing the core structures and algorithms for modularizing Node-RED workflows inside the `internal/syncflow/` Go package.

First, the Sync State Tracker: You will define the Go structs corresponding to the schema of the local `.build/sync_state.json` state tracking file. This tracking database tracks the files, their associated Node-RED IDs, node types (tab or subflow), last known content hashes, and last known modification times. You will implement utility functions to load this state from disk, save updates back to `.build/sync_state.json`, and track additions, deletions, or modifications bidirectionally.

Second, the Partitioning Engine: Node-RED represents its workspace as a single flat array of JSON nodes. You will implement partition grouping logic that groups this array by its parent root. Nodes of type `tab` represent root flows, and any node with a matching `z` property is grouped into that tab's partition. Nodes of type `subflow` represent root subflow definitions, and any node with a matching `z` property is grouped into that subflow's partition. Nodes without a `z` property (or where `z` is empty) are categorized as global configurations. This module forms the foundational analytical layer of the bidirectional flow sync engine.
