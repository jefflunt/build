# Rewrite the seven modular subflows under 'subflows/' (including dev, tester, boss, lead-dev, move-workflow, query-work, and sweep) to execute status, assignee, comment, and audit log updates through standard Go CLI 'build task update' command invocations instead of executing raw 'sqlite3' CLI utility queries.

Currently, the seven modular Node-RED subflows (boss, dev, tester, lead-dev, move-workflow, query-work, and sweep) are tightly coupled to the underlying database. They execute raw SQLite mutations and insert statements (for tasks, comments, and audit logs) directly via bash execution of the 'sqlite3' CLI. This pattern bypasses the Go CLI's domain validation, transaction safety, and schema abstraction, creating maintenance and schema evolution risks.

This task refactors all seven subflows under the 'subflows/' directory to completely replace direct 'sqlite3' update and insert operations with standard, flag-driven CLI calls to 'build task update'. The 'build task update' subcommand natively supports multi-attribute updates, automatic transaction handling, and simultaneous creation of audit logs and comments using unified parameters such as '--id', '--status', '--agent-id', '--comment', and '--audit-action'.

By executing updates through the Go CLI command, we achieve complete database abstraction for the orchestration layer, ensuring that Node-RED subflows operate as pure clients of the CLI interface. This transition secures transaction boundaries, enforces centralized validation rules, and significantly simplifies the JSON-based subflow definitions.
